# Проверка Gemini Notebook Assistant

## Установка расширения

1. Откройте `chrome://extensions/` и включите режим разработчика.
2. Нажмите «Загрузить распакованное расширение» и выберите папку с `manifest.json`.
3. Войдите в Google на `https://notebook.google.com/`.
4. Откройте расширение, выберите аккаунт и блокнот.

Расширение работает непосредственно из исходников. Node.js используется только для разработки и тестов.
После изменения файлов перезагрузите расширение на `chrome://extensions/`, затем обновите открытые страницы Notebook.
Это создаёт новый контекст content script вместо недействительного контекста предыдущей версии.

## Автоматические проверки

Требуется Node.js 22 или новее. Выполняйте команды из корня репозитория:

```sh
npm ci
npx playwright install chromium
npm test
```

Отдельные проверки:

```sh
npm run check
npm run test:unit
npm run test:browser
npx playwright show-report
```

- `check` проверяет синтаксис JavaScript, JSON, файлы манифеста и локали, включая объявления подстановок Chrome.
- `test:unit` проверяет API, конкурентный доступ к очереди и истории, повторные попытки, аккаунты, парсеры, отмену, настройки и обработчики команд.
- `tests/unit/reliability.test.cjs` и `tests/browser/reliability.spec.cjs` проверяют запоздавшую авторизацию, потерю ответа после записи на сервере, частичный импорт и запуск новой очереди после отмены старой.
- `test:browser` загружает настоящее расширение MV3 в Chromium: popup, content script, service worker, `chrome.storage`, обмен сообщениями, offscreen XML DOM и Chrome Debugger.
- В браузерных тестах ответы Google и YouTube задаются фикстурами. PDF создаётся настоящим `Page.printToPDF`; тест сравнивает загруженные байты с результатом печати.
- Тест перезапуска закрывает и запускает Chromium с тем же временным профилем. После запуска API подменяется на границе клиента из-за ограничений перехвата CDP для уже зарегистрированного worker.

HTML-отчёт находится в `playwright-report/index.html`, трассы неудачных сценариев — в `test-results/`.
Обе папки и `node_modules/` исключены из Git.

## Подготовка архивов

```sh
npm run package
```

Команда создаёт установочный ZIP, ZIP исходников, распакованные папки `dist/extension/` и `dist/github-update/`, описание выпуска и контрольные суммы SHA-256.
Набор входных файлов задан упаковщиком явно. Готовые файлы расширения проверяются на наличие зависимостей HTML и манифеста; содержимое обоих архивов сверяется с исходниками после сжатия.
При одинаковых входных файлах ZIP-архивы воспроизводимы: имена отсортированы, дата записей фиксирована.

Тесты упаковки проверяют состав, целостность, воспроизводимость, SHA-256 и загрузку готовой папки расширения в Chromium.
Порядок загрузки файлов в репозиторий и публикации Release: [GITHUB_UPDATE.md](GITHUB_UPDATE.md).

### Повторный запуск в текущем Windows-окружении

В ходе проверки установлены переносимые Node.js и Chromium в `%LOCALAPPDATA%\Temp\opencode`.
Если `node` ещё не добавлен в системный PATH, можно использовать их в текущей PowerShell-сессии:

```powershell
$tools = "$env:LOCALAPPDATA\Temp\opencode"
$env:PATH = "$tools\node-v24.22.2-win-x64;" + $env:PATH
$env:PLAYWRIGHT_BROWSERS_PATH = "$tools\playwright-browsers"
npm.cmd test
```

## Сквозные проверки Google

Используйте отдельный тестовый блокнот и документ Drive. Матрица фактически выполненных проверок приведена в [TEST_REPORT.md](TEST_REPORT.md).

1. Загрузите список блокнотов и создайте новый блокнот.
2. Добавьте веб-страницу, текст и YouTube-видео; проверьте появление источников повторным чтением блокнота.
3. Сохраните тестовую страницу как PDF и дождитесь обработки файла Google.
4. На странице YouTube загрузите комментарии, выберите сортировку и лимит, запустите парсинг и проверьте текстовый источник.
5. Добавьте две страницы в очередь. Дождитесь статуса завершения и проверьте оба источника в блокноте.
6. Добавьте Google-документ через Drive. Измените документ после импорта, запустите Sync Drive и проверьте обновление источника.
7. Удалите выбранные тестовые источники через popup и плавающую панель; повторно загрузите список источников.

В узком окне интерфейс Google может показывать вкладки `Sources`, `Чат`, `Studio`.
Откройте `Sources`, чтобы строки источников стали видимыми и получили чекбоксы расширения.
Если у нескольких источников одинаковые названия и Google не предоставляет их ID в DOM, используйте раздел «Источники» в popup: там чекбоксы привязаны непосредственно к ID API.

## Детали, важные для повторных проверок

- Очередь хранит аккаунт и блокнот на момент запуска. Переключение аккаунта не перенаправляет уже запущенную очередь.
- Используются до трёх попыток обработки элемента. Подтверждённый отказ сервера позволяет повторную отправку. После сетевого обрыва, ответа HTTP 5xx или повреждённого ответа исход записи считается неопределённым: последующие попытки сверяют новые ID источников с сохранённым снимком и не повторяют POST.
- После третьей ошибки элемент остаётся в очереди. Для неподтверждённой записи кнопка «Повторить ошибочные элементы» снова проверяет исходный блокнот. Если подтвердить импорт не удалось, проверьте источник в Google перед отдельным новым добавлением.
- Снимок неопределённой попытки сохраняется при перезапуске worker и в резервной копии. Старый источник с тем же URL не засчитывается как результат новой попытки.
- Очистка очереди останавливает последующие элементы; уже отправленный запрос может завершиться. Новая очередь продолжает работу после завершения этого запроса, без ожидания watchdog.
- Миллисекундные задержки обслуживаются таймером, пока service worker работает. `chrome.alarms` восстанавливает обработку после приостановки; пробуждение может задержаться до интервала watchdog.
- Прерванный перезапуском worker парсинг комментариев отображается как прерванный и запускается заново пользователем.
- RSS/Atom/Sitemap требуют доступа к домену ленты. Для дочерних Sitemap на другом домене также требуется разрешение на этот домен.
- История хранит до 500 записей. Резервная копия включает настройки, очередь, историю и позицию панели; активные задания и идентификаторы вкладок не восстанавливаются как запущенная работа.
- При частично успешном массовом импорте уже добавленные URL записываются в историю. В popup для повторного добавления остаются ошибочные и неотправленные URL; в менеджере вкладок успешно обработанные элементы снимаются с выбора. Неподтверждённые записи показаны отдельно и исключены из повторной отправки.
